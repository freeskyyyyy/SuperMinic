### 2026-11-19 优化器和学习率

图 3a 的单卡自训须从随机初始化开始，并通过作者 `train.py` 传入 `--runner.table-a5`。该选项只负责三套 Adam 和学习率日程。世界模型与价值网络沿用 Adam 默认 betas，策略使用 `(0.9, 0.95)`。当两处初始学习率均为默认的 `2e-4` 时，外层迭代 0、125,000、250,000 对应 `2e-4`、`1.03e-4` 和 `6e-6`。第 250,000 次迭代后保持 `6e-6`。续训从检查点的 `next_step` 计算日程。原公开训练模式及其旧检查点沿用各自的优化器类型。

已同步到 Spark。针对性 CPU 测试 23 项通过，覆盖 Adam 参数归属、日程边界、续训、世界模型损失和回放池恢复。Spark CUDA 微型测试确认三个真实 Adam 使用设备上的学习率张量，CUDA Graph 重放后参数按 `6e-6` 更新。小样本动作跟踪与全库训练待执行。

## 原版入口的剩余工作

1. 作者的 `MotionLoader` 读取根姿态、根速度和关节状态六个数组。现有 NPZ 可从 pelvis 对应的 `body_*` 列取四个根状态数组，再保留 `joint_pos`、`joint_vel` 与 `joint_names`。正式库按保留清单顺序打包。以本次帧数按 71 维 FP32 计算，六个数组约为 12.52 GiB。现有打包器会先读入所有片段再拼接，应在全量打包前核验峰值。
2. 固定提交中的 `benchmark.py` 测的是仿真和世界模型吞吐。图 3a 评估需要从每条动作首帧执行，足底摩擦系数 1.0，关闭域随机化和观测噪声，并按附录 A 的终止条件统计失败。独立按片段评估与批量合并仍待实现和验收。
3. 全库运行规模及实际更新比例仍需验收。课程优先，研究作业按独立 GPU 时段执行。

验证包括本机 11 项筛选边界核对、Spark 512 段 CPU 预检和 142,220 段全量 CPU 筛选。全量执行成功耗时约 141 秒。本阶段未启动训练。

## Spark 全库训练准备

2026-11-19，`supermimic-research` 的 cgroup 内存上限确认为 64 GiB，额外 swap 为 0，容器可见 NVIDIA GB10。直接按用户确认的筛选清单打包原有 50 Hz FP32 NPZ，保留根状态、关节状态、片段顺序和边界。打包未重采样。容器内路径为 `/workspace/data/bones_seed_129491_mjlab_fp32`。打包与训练入口参数解析通过，尚未运行训练。

在 Spark 的 shell 执行以下命令可从随机初始化开始。参数包含全库、512 环境、世界模型与策略 batch 各 128。世界模型每次外层更新做 10 个批次，`replay_ratio=9` 对应约 0.4 次外层更新／迭代。首轮预算 1001 次迭代，在索引 1000 保存可续训检查点。运行目录由日志的 `[INFO] Logging to` 给出。

```bash
docker exec -e WANDB_MODE=offline -e PYTHONUNBUFFERED=1 \
  -e MPLCONFIGDIR=/tmp/supermimic-matplotlib \
  -e TRITON_CACHE_DIR=/workspace/cache/triton \
  -e WANDB_DATA_DIR=/workspace/cache/wandb \
  -w /workspace/src/supermimic supermimic-research \
  .venv/bin/python src/supermimic/scripts/train.py SuperMimic-GenCoord-G1 \
  --motion-file /workspace/data/bones_seed_129491_mjlab_fp32 \
  --device cuda:0 --num-envs 512 --env.seed 42 \
  --runner.run-name figure3a_full512_a5_seed42 \
  --runner.table-a5 True --runner.actor-obs proprio --runner.history-length 10 \
  --runner.wm.horizon 9 --runner.wm.num-batches 10 --runner.wm.batch-size 128 \
  --runner.policy.batch-size 128 --runner.replay-ratio 9 \
  --runner.max-iterations 1001 --runner.save-interval 1000 --runner.log-interval 50 \
  --runner.checkpoint-training True
```

检查点为运行目录下的 `training_state.pt`。续训时传入 `--runner.resume-path` 和该文件的容器内路径，并将 `--runner.max-iterations` 设为目标总迭代上限。全库轨迹数量与论文差 23 段，首轮环境数与批大小按 Spark 配置缩减。

研究容器以 UID 1000 运行，`HOME=/`。上面的 `TRITON_CACHE_DIR` 将编译缓存指向挂载盘的可写目录，避免首次编译尝试创建 `/.triton`。已在同一容器验证默认路径复现权限错误，指定缓存路径后 CUDA Inductor 能编译并正确执行独立算子。

### 检查点配置补充

论文附录图 A.1 的“每 4,000 次评估”是评估间隔；作者训练代码的模型文件保存间隔默认 1,000。长训脚本保留每 1,000 次覆盖式保存 `training_state.pt`，用于续训；额外在 4,000 次间隔把世界模型、actor 和 critic 复制到 `eval_checkpoints/iteration_*`，供训练后按论文协议评估。模型 artifact 上传 W&B 已关闭，避免无网络环境下上传警告；标量仍通过 `WANDB_MODE=offline` 本地记录。此处新增的是复现所需的本地评估快照，不代表论文要求每 4,000 次保存模型文件。设置已同步到 Spark；已运行的进程不会加载后来同步的代码。

### 1024 动作检查点评估入口

固定样本清单 [figure3a_probe1024.txt](../data/manifests/figure3a_probe1024.txt) 沿用第三方资源测试用的 1024 段动作。核对后这 1024 段全部属于本次按附录 E 重建的训练库；合计 327,968 帧、1.822 小时，单段最多 999 帧。该集合适合快速检查训练曲线，不是作者公布的评估子集，也不是全库最终结果。

作者版评估入口为 `src/supermimic/scripts/evaluate_figure3a.py`。它直接读取作者训练状态或 `eval_checkpoints/iteration_*`，用作者 G1 任务构造环境，从每段首帧评估；关闭动作/观测噪声和随机化，固定足底摩擦 1.0。结果写入 `summary.json` 与 `per_motion.csv`，分别报告逐动作归一化回报均值、按完整动作长度加权的归一化回报和失败数。归一化分母按完整动作应执行步数计算，因此提前失败会拉低回报。评估不记录视频；如需定性画面，再单独播放代表动作。

为在一个批次并行重置到不同动作首帧，`mjlab_research` 的 `MotionCommand` 增加了 `reset_to_frames` 向量化接口；现有单帧 `reset_to_frame` 仍委托给它。此改动只服务评估入口，不改变训练更新或模拟参数。
