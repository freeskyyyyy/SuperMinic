### 9.3 指标口径必须先核实

当前上游 `benchmark.py` 使用 `sum(reward)/(0.1*实际执行步数)`，再给出动作平均和实际步数加权平均。提前失败会缩短分母，所以高回报不等于整段成功。

3. 如需与论文的整段归一化严格比较，先核对论文评价公式和末帧/超时语义，再额外生成独立字段；不覆盖原始分数。

## 10. P5：自主短训与重启，最小闭环通过后先测资源

**目的：**确认之后能自己训练和研究，不用长训来解决回放兼容问题。

R2顺序：P3最小闭环通过后即可进行本节首轮短训和资源计时，不等待P4全量评估。完整集合评估与正式训练均使用前期测量结果安排规模。

### 10.1 从零短训，先验证训练链路

- [ ] 固定四动作、seed=42，64个训练环境，WM/policy batch各64；保持原网络、k=8、H=32和观测布局。
- [ ] 运行至少300迭代，越过默认40迭代 warmup；保存初始/结束参数、实际更新次数、损失和计时。
- [ ] 检查世界模型、策略、价值网络均有真实更新，梯度/参数有限；短训结果不要求成熟跟踪。

```bash
env -u PYTHONPATH uv run --no-sync sm-train \
```

该计时上限仅为起步预算，不保证首次编译后一定更新到300。记录不足时延长，达到验证目标即保存退出。`total_iterations=320000` 保持学习率计划，不能为提前结束随便改成300或100000；`max_hours` 在日志边界检查，也不是严格到秒的截止器。

### 10.2 先用自己的小集合检查点验证重启

- [ ] 保持完全相同数据、名称顺序、网络、采样配置与种子；`--resume` 指向自己的新检查点，`--run-name` 使用新目录。

- [ ] 新进程加载保存后的策略，重新做固定动作评估。记录重启前后结果。

**已确认的恢复边界：**上游保存优化器和采样统计，但不保存经验缓冲区、仿真状态和完整随机数状态，加载后重新 warmup。`Trainer.load()` 不自动采用保存的全套配置，因此启动参数必须与目标实验匹配。这是可继续训练，不是逐步相同的精确续跑。

### 10.3 发布 e8 权重续训单独处理

上游 `load()` 会直接复制 `bin_return`、`bin_memory`。换成少量动作，或者把129943训练集换成129491评价集，会导致尺寸或动作含义不匹配；即使形状相同也必须核对名称与顺序。

后续只选择与实际条件相符的一条路线：

- **原实验延续：**能重建同顺序训练动作库时，恢复嵌入配置、优化器和采样统计，再继续100000之后的迭代。Spark单GPU与原4GPU训练的有效采样量、梯度聚合及学习率仍有差异，需要披露。
- **小集合微调：**不能重建原库时，新建明确的 warm-start 入口，仅导入兼容模型参数，重新建立本次数据采样与训练状态；可使用预训练网络，不宣称恢复原实验。只在实际进入此任务时补最小实现及针对性测试。

**产物：**`reports/P5_训练与重启验收.md`、自己的检查点、完整配置与日志。

**通过标准：**自己的训练链路和重启真实通过；不把300迭代当作收敛，不把微调写成完全恢复发布实验。
