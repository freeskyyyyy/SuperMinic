# P4：下载等待期间的数据与评估准备核对

日期：2026-11-16。基于本机固定提交 ba6105349069bf040f1fdad60873d13138d505a2 的静态源码核对。此次不启动训练、转换或下载，不修改上游算法。下载进行中由用户报告；尚未检查最终压缩包。

## 1. 下载后的执行顺序

1. 文件预期大小 23499973647 字节。完成后检查 gzip 完整性、归档成员路径与解压空间；本地 SHA256 作为后续身份记录，不能单凭本地哈希声称已与上游校验值一致。
2. 先查看归档结构，确定 CSV 实际根目录，检查是否存在不同目录下同名 CSV。转换器递归寻找 CSV，但输出使用 src.stem 平铺；同名文件会指向相同输出位置，因此必须在启动转换前核对。本次没有证据表明该归档实际存在重名。
3. 使用项目原转换器，显式指定 input_fps=120、output_fps=50，workers=2 起步。默认 input_fps 是30，不能原样沿用 LAFAN 命令。
4. 检查转换失败日志及 manifest.csv；脚本捕获单文件异常后仍可正常退出，因此退出码0不等于所有文件转换成功。重复运行跳过已有 NPZ，manifest 会重扫输出目录；保留首次失败日志。
5. 对转换结果运行名字与可行性过滤，生成 manifest_filtered.csv。过滤不删除 NPZ，后续评估和建库必须明确传入此清单。
6. 根据真实清单固定16–32段小集合（普通和困难动作），先做数据抽查与单环境评估；通过后比较少量并行结果，再分片扩大。

## 2. 数据格式与转换

依据 src/supermimic/data/motion_convert.py：

| 项目 | BONES CSV | 转换后 |
|---|---|---|
| 识别 | 首行以 Frame,root_translateX 开头 | 转换器自动选 BONES 分支 |
| 根位置 | cm | 除100，单位m |
| 根朝向 | xyz欧拉角，度 | SciPy Rotation 转四元数；NPZ刚体四元数为wxyz |
| 关节角 | 29关节，度 | 转rad，并检查列名与G1顺序 |
| 时间 | 120 Hz（项目文档所述；实包仍须抽查） | 50 Hz |
| 速度 | 转换时计算 | 关节与根线速度由重采样信号求导，刚体状态由CPU MuJoCo运动学计算 |

转换命令模板（在现有研究容器、源码目录执行；CSV_ROOT需在检查归档后替换）：

```bash
.venv/bin/python scripts/data/csv_to_npz_batch.py \
  --input-dir "$CSV_ROOT" \
  --output-dir /workspace/data/processed/bones_seed \
  --input-fps 120 --output-fps 50 --workers 2

.venv/bin/python scripts/data/filter_bones_seed.py \
  --npz-dir /workspace/data/processed/bones_seed --workers 2
```

此处为已核对参数的待执行模板，不表示转换已验收。

## 3. 清单、过滤与排序

- filter_bones_seed.py 的名字过滤包含 cartwheel、handstand 等杂技关键词；还检查悬空支撑、穿地、静止站立时脚底悬浮。脚本阈值包含第三方选择，不等于每项均由论文唯一指定。
- discover_npz() 只读取输出目录第一层NPZ，按路径排序；manifest的keep列决定保留集合，clip-list只进一步限定集合。
- clip-list中行的次序不会决定执行次序：代码将名称转为set，再在已排序文件中筛选。必须保存实际发现顺序，不能声称按文本顺序运行。
- 训练清单和评价清单分别保存。e8历史训练129943段、当前发布过滤评价129491段、论文129514段，不能混用或人为凑数。
- 预训练模型的bin_return/bin_memory依赖训练库名称和顺序；不能把当前过滤评价库直接当原训练库恢复采样统计。

## 4. 评估协议与命令

benchmark.py固定从首帧开始，seed=0、无观测/动作/重置噪声、无域随机化，使用物理仿真闭环。CLI从检查点配置读取future_frames和anchor_obs，严格加载策略。

```bash
.venv/bin/python scripts/eval_benchmark.py \
  --ckpt /workspace/checkpoints/upstream/e8-boneseed-100k/e8_boneseed_ckpt_0100000.pt \
  --npz-dir /workspace/data/processed/bones_seed \
  --manifest /workspace/data/processed/bones_seed/manifest_filtered.csv \
  --clip-list /workspace/data/manifests/bones_mini_eval.txt \
  --num-envs 1 --device cuda:0 \
  --out "$RUN/metrics/bones_mini.json"
```

RUN及其metrics目录需在启动前创建；小集合清单尚未生成，不能现在执行此命令。原CLI默认1024环境，本项目不采用这一默认值起跑。

指标保留上游原字段：

- 单动作 norm_return = 累计奖励 / (0.1 × 实际执行步数)。提前失败后分母缩短，因此必须同时报告 failed、steps、frames、fail_step。
- mean_norm_return：逐动作得分算术平均。
- step_weighted_norm_return：按实际执行步数加权；不等于按完整参考动作长度加权。
- 同时输出失败数/率、实际与参考长度比例及失败时间（按50Hz换算；末帧语义另核实），不覆盖上游得分。
- 公开0.930属于发布者汇总；目前未取得其逐动作原始JSON，不能声称已逐项对齐，也不能仅凭四舍五入的公开数确定汇总字段。

## 5. 全库评估的内存限制

run_benchmark()把当前分片全部npz_files传入make_env，但不传compact_library；配置默认false。降低num_envs不等于减少参考库加载量，不能直接将全量目录交给它并认定16GiB足够。

当前先使用明确的小清单，后续按实际帧数和资源测量分片。原merge_benchmark_shards.py直接拼接结果，没有重名/缺项核对；合并前用预期清单核对各片名称的并集与交集。这是实际数据完整性要求，暂不新增通用框架。

训练用build_library.py另走compact路径，71维fp16参考状态，但构建阶段同时保留items及concatenate结果，峰值高于最终文件大小。全库构建前需按实得帧数估算，再决定容器配额；不直接在16GiB内启动。
