## 2. 必须披露的安装与配置处理

1. 大型依赖在代理路径重复下载，后改为从原锁提取七个wheel、独立连接续传，大小与SHA256全部匹配。原wheel保留于cache/wheelhouse，清单environment/wheelhouse-manifest.json。
2. 本地预装后的普通离线sync仍请求原始URL。实际采用：保留这七个已校验的原锁版本，使用`--locked --offline --inexact --no-install-package ...`补齐其余149个包，原锁未变。不能说未经处理的原生安装命令已直接通过。
3. nvidia-cusparselt-cu13 0.8.1的原始包WHEEL标记为manylinux2014_sbsa，但共享库ELF e_machine=183，确为AArch64。仅将已安装WHEEL标记修正为manylinux2014_aarch64并更新对应RECORD条目，二进制不变。原WHEEL/RECORD与patch.json保留于environment/patches/nvidia-cusparselt-cu13-0.8.1。
4. 首次渲染回退Mesa/llvmpipe。容器有libEGL_nvidia.so.0而缺10_nvidia.json；补齐新研究容器的供应商配置后实测NVIDIA硬件EGL通过，并写入新Dockerfile。
5. Windows编辑脚本时曾引入CRLF，第一批转换/测试未执行，虽末尾help命令返回0也不计通过。已修正LF，清理仅由CR产生的错误路径后重跑；原失败日志保留。

运行使用`.venv/bin/python`或`uv run --no-sync`，避免自动sync为来源记录重新下载已校验包。环境重建按environment中的实际安装脚本执行；普通上游README的自动同步命令不等同本环境安装流程。

未更改宿主驱动、课程包、旧官方环境；没有增加全局代理或网络服务。

## 3. 实际验证

- PyTorch CUDA矩阵前后向、梯度有限性：通过。
- Warp CUDA实际平方kernel与CPU结果一致：通过，设备sm_121。
- G1加载：nq=36、nv=35，即自由根加29关节。
- NVIDIA EGL实际120×160 RGB渲染：通过。
- 上游针对性测试：**22 passed，0 skipped**，39.92秒；覆盖CSV重采样/关节顺序、FK与速度、紧凑/完整库、奖励、观测、终止、状态读写、仿真条件、clip边界、GAE和k=8回放采样。
- 训练入口help：通过；仅检查入口，没有启动训练。
- 1条torch.jit.script弃用警告，未因无关警告修改上游实现。

k=8测试覆盖9状态、8动作，不移植旧官方窗口补丁。物理fixture为32环境，包含40步随机动作、60步零动作及clip末端超时检查；不能沿用旧官方64环境1000步的结果作为本项目证据。
