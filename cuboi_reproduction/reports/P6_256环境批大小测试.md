# P6：256环境的训练批大小测试

2026-11-16。固定四段LAFAN1、seed42、256环境、replay容量200、k8、H32、320000迭代学习率计划；WM与policy批大小同时取128和256。两档串行、原网络与原Trainer，不改奖励、动力学或观测。本报告是资源与运行正确性测试，不是收敛对照。

## 资源配置及实际故障

用户已确认计划并授权执行：研究容器由4CPU/16GiB调整为10CPU/64GiB，MemorySwap同64GiB，不提供额外swap。实际值：NanoCpus=10000000000、Memory=68719476736、MemorySwap=68719476736；该限额已生效，不是实际预占64GiB，也不隔离GPU算力。

docker update后容器nvidia-smi返回NVML Unknown Error，宿主GPU正常；首个批128编号01的测量失败，没有记作通过。与NVIDIA文档描述的资源/cgroup更新后容器失去GPU访问问题一致；仅重启当时空闲研究容器，GPU查询恢复，限额保持。未重启Docker服务、修改驱动或课程，独立下载容器未停止。

官方故障说明：https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/troubleshooting.html#containers-losing-access-to-gpus-with-error-failed-to-initialize-nvml-unknown-error

## 实际结果

| 项目 | 批大小128 | 批大小256 |
|---|---:|---:|
| 迭代 / 更新 | 400 / 144 | 350 / 124 |
| 总耗时（含编译/初始化/保存） | 302.25秒 | 306.75秒 |
| 最后4个50迭代窗口速度中位数 | 3.70次/秒 | 3.85次/秒 |
| 容器采样内存峰值 | 8.46GiB | 10.59GiB |
| 子进程RSS峰值 | 5.05GiB | 5.25GiB |
| 平均CPU核当量 | 1.32 | 1.35 |
| 整卡采样GPU利用率峰值 | 91% | 91% |
| 主机最小可用内存 | 106.06GiB | 105.19GiB |

两档均exit_code=0，世界模型、策略、critic参数实际更新且有限，均超过300迭代，并包含至少200个首次编译后的迭代。第一个50迭代窗口的policy累计计时约180.1/196.6秒，主要受首次编译影响，不能拿冷启动总时间直接计算稳态速度。

最后200迭代的sim/wm/policy平均每50迭代计时：批128为1.825/3.875/7.200秒，批256为1.525/3.875/6.950秒；包含系统波动，不认为256必然更快。日志速度仅保留一位小数，表格中位数是据此计算的近似值。

容器内存含缓存与检查点写入，RSS/cgroup不是完整GPU统一内存账目。旧批64在4CPU/16GiB、编译缓存状态不同的条件下测得，不能把跨轮差异全归因于批大小。

## 后续选择

对本次四动作测试，256环境、WM/policy batch256可运行，未出现内存不足；可以作为BONES数据就绪后的小集合训练起步候选。批256没有明显降低本轮迭代吞吐，每次更新处理更多样本，但不能据此证明学习质量、收敛速度或最优批量。

正式训练仍须计入BONES动作库、回放容量及目标训练清单；加载实际数据后做一次必要短测，再确定长期配置。10CPU/64GiB保留为下一阶段预算，不因目前只用约10GiB就自动提高或降低。课程重GPU负载与研究的并行性能未验收。
